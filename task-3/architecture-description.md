# Описание целевой архитектуры по этапам

## Этап 1

Выделяются два домена, вводятся событийная интеграция и каталог схем.

**Домен "Финансовые отчёты"**:
- **Шина финансовых событий** - обработка потоков финансовых событий "почти в
  реальном времени".
- **Стыковочная шина ESB -> ФинТех** - очереди/темы, передающие сообщения от
  ESB в домен Финтеха и обратно; мост между старым ESB и новым доменом.
- **Защитный стыковочный слой** - антикоррупционный слой (ACL):
  форматно-логический контроль, интеграционная логика (перевод событий из
  форматов внешнего мира во внутренние), абстрагирование от внешних систем.
- **Аналитическое хранилище** - общее хранилище для аналитики и операционного
  управления; отчёты Power BI строятся поверх Greenplum.

**Домен "Управление данными"**:
- **Каталог схем и метаданных** - реестр всех применяемых в компании схем и
  метаданных; потребляется хранилищами, шинами и аналитиками.

**Сохраняются старые системы:**
- **DWH**
- **Служебная шина предприятия**
- **Power BI**
- **Внутренние службы**
- **Внутренние службы ИИ**
- **ФинТех Службы**.

Финтех уже развязан через Kafka и пограничный слой, но ESB и DWH ещё в
эксплуатации.

## Этап 2

Добавляется медицинский домен и оформляется домен внутреннего управления.

**Домен "Медицинские данные"**:
- **Медицинская база данных** - хранение и обработка структурированных и
  неструктурированных медицинских данных (анализы, назначения, истории
  болезней, диагнозы, снимки).
- **Шина медицинских данных** - хранит историю медицинских данных/событий.
- **Аналитическая система (Clickhouse, ETL, CDC)** - аналитическая подсистема
  для работы с медицинскими данными; получает выгрузки через CDC и ETL.
- **Стыковочный слой** - вызов необходимых процедур в ESB для сохранения и
  обработки медицинских событий.
- работа с **Внутренними службами ИИ**;
- работа с анализами во внешних лабораторных системаx.
- **МедИС** - переключается на системы домена, вместо DWH.

**Домен "Внутреннее управление"**: Домен оформляется как отдельный, но пока
остаётся на базе прежних систем.

Каталог схем и метаданных теперь раздаёт метаданные всем доменам.

## Этап 3

**Разделение хранилищ:**
- **Оперативное хранилище** - только операционное управление.
- **Аналитическое хранилище внутреннего управления** - только аналитика по
  управленческим данным.
- **Аналитическое хранилище медицинского домена** - аналитика и обработка
  медицинских данных.
- **Аналитическое хранилище финансового домена** - аналитика и обработка
  финансовых данных.

**Домен "Внутреннее управление"**:
- **Шина событий внутреннего управления**.
- **Стыковочный слой** - нужен для подключения к другим доменам, перевода
  внешних событий во внутренние и так далее.
- Публикует финансово значимые события (выставление счетов, оплаты, заявки на
  ТМЦ и прочее) в финансовый домен.
- Переезд оперативного хранилища с устаревшего SQL Server на PostgreSQL.

**Замена ESB прямой событийной интеграцией:** центральная служебная шина
предприятия исчезает; домены публикуют события в своих шинах, потребляют
события других доменов через пограничные слои.

**Из медицинского домена убирается стыковочный слой**, поскольку медицинский
домен не потребляет события из других доменов.

**Каталог схем и метаданных** остаётся сквозным реестром для всех доменов.
