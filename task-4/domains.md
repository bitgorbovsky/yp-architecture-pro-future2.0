# Определение доменов

Принципы разбиения:

- **Границы - по деловым процессам**
- **Автономность контекстов**
- **Слабая связанность через события**

**Ограничение**: содержимое медицинских карт, историй болезней и результатов
исследований не передаётся в аналитику. Вместо этого передаются обезличенные
факты (оказание медицинских услуг, проведений обследований, требующих оплаты,
длительность приёма и так далее, то есть, то, что нужно финансам и управлению.

## Домены

### Медицинские данные

**Назначение и границы**: Ведение медицинских карт, историй болезней, исследований, назначений и диагнозов. Аналитика медицинских данных с помощью средств ИИ: постановка диагнозов и рекомендаций на основе моделей ИИ поверх медицинских данных.

**Источник данных**: Личный кабинет оператора МедИС, внешние лабораторные системы, личный кабинет пацентов, государственные системы здравохранения.

**Домены-потребители данных**:
- **Финтех** - для финансового обеспечения.
- **Внутреннее управление** - товарно-материальное обеспечение, управление персоналом, планирование.

**Доменные агрегаты и сущности**:

| Агрегат                        | Входящие сущности                                    | Ключевые инварианты                                                |
| ------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------ |
| **Медицинская Карта Пациента** | **Личные Данные**, **Перечень Историй Болезни**      | Карта уникальна на пациента. ЛДн доступны только внутри контекста. |
| **История Болезни**            | **Записи приёма**, **Лечение**                       | Привязана к одной карте. Закрытый эпизод не изменяется.            |
| **Исследование**               | **Результат Исследования**, **Файл с Исследованием** | Результат неизменяем после подтверждения                           |
| **Назначение**                 | ПереченьПроцедур/Препаратов                          | Создаётся только в рамках открытого эпизода                        |
| **Диагноз**                    | **Код МКБ**, **Обоснование**                         | Ставится уполномоченным медработником                              |
**События домена**:

| Событие                        | Данные                                    | Потребители                              |
| ------------------------------ | ----------------------------------------- | ---------------------------------------- |
| **Исследование Завершено**     | № Исследования, № пациента, тип, статус   | Аналитика ИИ                             |
| **Диагноз Поставлен**          | № эпизода лечения, код МКБ                | Аналитика ИИ                             |
| **Назначение Создано**         | № назначения, перечень услуг и препаратов | Внутреннее управление, Финтех            |
| **Медицинская Услуга Оказана** | № услуги, № клиники, стоимость, дата      | Финтех, Внутреннее управление, Аналитика |

| Домен / контекст       | Назначение и границы                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| Финтех                 | Счета, платежи, кредиты, банковские счета и транзакции. Подчиняется регулятору, требуется банковская лицензия. |
| Внутреннее управление  | Управление клиниками, персоналом, инвентаризацией/ТМЦ, внутренние заявки и счета.                              |
| Аналитика и отчётность | Портал самообслуживания и потоковые витрины.                                                                   |
| Управление данными     | Каталог схем и метаданных, контракты данных, происхождение данных.                                             |

### 3.2. Финтех (Платежи и банкинг) — Core

**Назначение и границы.** Финансовые операции: выставление счетов за оказанные услуги, приём платежей, ведение банковских счетов, выдача и обслуживание кредитов, регистрация транзакций. Регулируемая деятельность.

**Ключевые агрегаты.**

| Агрегат | Входящие сущности / VO | Ключевые инварианты |
|---|---|---|
| `Счёт (Invoice)` | ПозицииСчёта, Сумма, Статус | Сумма = сумме позиций; счёт нельзя оплатить дважды |
| `Платёж` | СпособОплаты, Сумма, Статус | Платёж привязан к счёту; сумма ≤ остатку по счёту |
| `БанковскийСчёт (Account)` | Баланс, Валюта, Владелец | Баланс не уходит ниже допустимого лимита |
| `Кредит` | ГрафикПлатежей, Ставка, Статус | Одобрение только при пройденном скоринге |
| `Транзакция` | Дебет/Кредит, Сумма, Метка времени | Двойная запись; неизменяема после проведения |

**Доменные события.**

| Событие | Полезная нагрузка | Потребители |
|---|---|---|
| `СчётВыставлен` | id счёта, id клиента, сумма | Аналитика, Внутреннее управление |
| `ПлатёжПроведён` | id платежа, id счёта, сумма, дата | Аналитика, Внутреннее управление |
| `КредитОдобрен` | id кредита, сумма, ставка | Аналитика |
| `ТранзакцияЗарегистрирована` | id транзакции, тип, сумма | Аналитика |

**Публикуемый язык.** Финансовые факты и агрегированные показатели; чувствительные реквизиты не публикуются, доступ регулируется по уровню.

### 3.3. ИИ-аналитика медицинских данных — Core

**Назначение и границы.** Обработка клинических данных ИИ-моделями: помощь в постановке диагнозов и формировании рекомендаций. Потребляет события клинического контекста, возвращает результаты вывода моделей.

**Ключевые агрегаты.**

| Агрегат | Входящие сущности / VO | Ключевые инварианты |
|---|---|---|
| `ЗапросНаОбработку` | id исследования, тип модели, статус | Один запрос — на одно исследование/эпизод |
| `РезультатВывода (Inference)` | Оценки/вероятности, Версия модели | Привязан к версии модели; неизменяем |
| `Рекомендация` | Текст рекомендации, Уверенность | Формируется только при завершённом выводе |

**Доменные события.**

| Событие | Полезная нагрузка | Потребители |
|---|---|---|
| `АнализОбработан` | id запроса, id исследования, статус | Клинический контекст |
| `ИИ-РекомендацияГотова` | id рекомендации, id эпизода, уверенность | Клинический контекст |

**Публикуемый язык.** Результаты вывода и рекомендации (в обезличенном виде), метаданные версии модели.

### 3.4. Внутреннее управление — Supporting

**Назначение и границы.** Управление клиниками, персоналом больниц, инвентаризацией (ТМЦ), внутренними заявками и счетами. Обеспечивает операционную деятельность сети клиник.

**Ключевые агрегаты.**

| Агрегат | Входящие сущности / VO | Ключевые инварианты |
|---|---|---|
| `Клиника` | Подразделения, Адрес, Профиль | Уникальный идентификатор клиники |
| `Сотрудник` | Должность, Квалификация | Один активный трудовой статус |
| `Расписание / Смена` | Слоты, Назначения персонала | Сотрудник не назначается на пересекающиеся смены |
| `ПозицияТМЦ` | Остаток, ЕдиницаУчёта | Остаток не отрицателен |
| `ЗаявкаНаТМЦ` | ПереченьПозиций, Статус | Заявка проводится при наличии согласования |

**Доменные события.**

| Событие | Полезная нагрузка | Потребители |
|---|---|---|
| `ЗаявкаНаТМЦСоздана` | id заявки, позиции, id клиники | Финтех, Аналитика |
| `ПерсоналНазначен` | id сотрудника, смена, клиника | Аналитика |
| `ИнвентарьСписан` | id позиции, количество, причина | Финтех, Аналитика |

**Публикуемый язык.** Факты управления клиниками, персоналом и ТМЦ.

### 3.5. Аналитика и отчётность (Витрина данных) — Supporting

**Назначение и границы.** Портал самообслуживания: сотрудник получает отчёты по любым срезам в пределах своего уровня доступа и конструирует собственные отчёты. Строит потоковые витрины на основе событий всех доменов. **Не включает** медицинские карты, истории болезней и результаты исследований — только обезличенные факты и финансово-управленческие данные. Это преимущественно read-модель (CQRS-проекции над потоком событий).

**Ключевые агрегаты (read-модели / проекции).**

| Агрегат | Входящие сущности / VO | Ключевые инварианты |
|---|---|---|
| `ОтчётныйДатасет` | Срезы, Метрики, ВременнойГоризонт | Строится только из разрешённых источников (без медкарт) |
| `КонструкторОтчёта` | Выбранные измерения/меры, Фильтры | Доступные поля ограничены уровнем доступа пользователя |
| `ПодпискаНаОтчёт` | Расписание, Получатели, Формат | Рассылка только в пределах уровня доступа |

**Доменные события.**

| Событие | Полезная нагрузка | Потребители |
|---|---|---|
| `ВитринаОбновлена` | id витрины, версия, отметка времени | Портал, Управление данными |
| `ОтчётСформирован` | id отчёта, id пользователя, статус | Портал |

**Разграничение доступа.** Уровень доступа применяется на уровне строк и столбцов (row-/column-level security) на основе оргструктуры и атрибутов пользователя (сквозная возможность IAM).

**Публикуемый язык.** Готовые витрины, отчётные датасеты, метаданные отчётов.

### 3.6. Управление данными (Data Governance) — Generic / Supporting

**Назначение и границы.** Каталог схем и метаданных, контракты данных между контекстами, происхождение данных (lineage), поддержка единого языка. Обеспечивает совместимость и управляемость событийного обмена.

**Ключевые агрегаты.**

| Агрегат | Входящие сущности / VO | Ключевые инварианты |
|---|---|---|
| `СхемаДанных` | Версия, Поля, Совместимость | Изменение схемы обратно совместимо (или новая мажорная версия) |
| `КонтрактДанных` | Издатель, Потребители, SLA | Контракт активен при согласовании сторон |
| `КаталожнаяЗапись (Lineage)` | Источник, Приёмник, Преобразования | Прослеживаемость происхождения данных |

**Доменные события.**

| Событие | Полезная нагрузка | Потребители |
|---|---|---|
| `СхемаЗарегистрирована` | id схемы, версия, владелец | Все контексты |
| `КонтрактИзменён` | id контракта, версия, стороны | Издатель и потребители контракта |

**Публикуемый язык.** Реестр схем, контракты, метаданные и происхождение данных.

## 5. Карта контекстов (Context Map)

Связи между контекстами и передаваемые данные. Взаимодействие асинхронное через шины событий; на этапе миграции доступ к данным легаси-DWH идёт через антикоррупционные слои (без прямого обращения к DWH).

| Контекст-источник       | Контекст-получатель   | Что передаётся                               | Шина                   |
| ----------------------- | --------------------- | -------------------------------------------- | ---------------------- |
| Клинический             | ИИ-аналитика          | Факты об исследованиях, диагнозах            | Медицинских данных     |
| ИИ-аналитика            | Клинический           | Результаты вывода, рекомендации              | Медицинских данных     |
| Клинический             | Финтех                | Факты оказанных услуг (основания для счетов) | Медицинских данных     |
| Клинический             | Внутреннее управление | Назначения, факты услуг                      | Медицинских данных     |
| Финтех                  | Аналитика             | Финансовые события                           | Финансовых событий     |
| Финтех                  | Внутреннее управление | Счета, платежи                               | Финансовых событий     |
| Внутреннее управление   | Финтех                | Заявки на ТМЦ, списания                      | Внутреннего управления |
| Внутреннее управление   | Аналитика             | События персонала, ТМЦ, клиник               | Внутреннего управления |
| Все доменные контексты  | Аналитика             | Обезличенные факты (без медкарт)             | Соответствующие шины   |
| Управление данными      | Все контексты         | Схемы, контракты, метаданные                 | Все шины               |
| DWH (легаси, через ACL) | Домены                | Исторические данные на этапе миграции        | Через ACL / CDC        |
