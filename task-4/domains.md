# Определение доменов

**Ограничение**: содержимое медицинских карт, историй болезней и результатов
исследований не передаётся в аналитику. Вместо этого передаются обезличенные
факты (оказание медицинских услуг, проведений обследований, требующих оплаты,
длительность приёма и так далее, то есть, то, что нужно финансам и управлению.

## Домены

### Медицинские данные

**Назначение и границы**: Ведение медицинских карт, историй болезней, исследований, назначений и диагнозов. Аналитика медицинских данных с помощью средств ИИ: постановка диагнозов и рекомендаций на основе моделей ИИ поверх медицинских данных.

**Источник данных**:
- Личный кабинет оператора МедИС;
- внешние лабораторные системы;
- личный кабинет пациентов;
- государственные системы здравоохранения.

**Домены-потребители данных**:
- **Финтех** - для финансового обеспечения.
- **Внутреннее управление** - товарно-материальное обеспечение, управление персоналом, планирование.

**Доменные агрегаты и сущности**:

| Агрегат                           | Входящие сущности                                    | Ключевые инварианты                                                          |
| --------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Медицинская Карта Пациента**    | **Личные Данные**, **Перечень Историй Болезни**      | Карта уникальна на пациента. Личные данные доступны только внутри контекста. |
| **История Болезни**               | **Записи приёма**, **Лечение**                       | Привязана к одной карте.                                                     |
| **Исследование**                  | **Результат Исследования**, **Файл с Исследованием** | Результат неизменяем после подтверждения.                                    |
| **Назначение**                    | **Перечень Процедур/Препаратов**                     | Создаётся только в рамках открытого эпизода.                                 |
| **Диагноз**                       | **Код МКБ**, **Обоснование**                         | Ставится уполномоченным медработником.                                       |
| **Запрос На Обработку Через  ИИ** | **№ Исследования**, **Тип Модели**, **Статус**       | Один запрос - на одно исследование.                                          |
| **Результат Вывода ИИ**           | **Оценки, Вероятности**, **Версия Модели**           | Привязан к версии модели, неизменяем.                                        |
| **Рекомендация ИИ**               | **Текст Рекомендации**, **Уровень достоверности**    | Формируется только при завершённом выводе.                                   |

**События домена**:

| Событие                        | Данные                                         | Потребители                                 |
| ------------------------------ | ---------------------------------------------- | ------------------------------------------- |
| **Назначение Создано**         | № назначения, перечень услуг и препаратов      | Внутреннее управление, Финтех               |
| **Медицинская Услуга Оказана** | № услуги, № клиники, стоимость, дата           | Финтех, Внутреннее управление, Аналитика    |
| **Исследование Начато**        | № Исследования, Дата, Время                    | Медицинские данные (внутридоменное событие) |
| **Исследование Завершено**     | № Исследования, Статус, Результат исследования | Медицинские данные (внутридоменное событие) |
| **Диагноз Поставлен**          | Текст диагноза, Код МКБ, Обоснование           | Медицинские данные (внутридоменное событие) |

### Финтех

**Назначение и границы**: Финансовые операции: выставление счетов за оказанные услуги, приём платежей, ведение банковских счетов, выдача и обслуживание кредитов, регистрация транзакций. Подчиняется регулятору, требуется банковская лицензия.

**Источник данных**:
- "Медицинские данные";
- "Внутреннее управление";
- банковские системы;
- платёжные шлюзы.

**Домены-потребители данных**:
- **Аналитика и отчётность** - финансовая отчётность и витрины.
- **Внутреннее управление** - сверка счетов и оплат по клиникам.

**Доменные агрегаты и сущности**:

| Агрегат             | Входящие сущности                              | Ключевые инварианты                                               |
| ------------------- | ---------------------------------------------- | ----------------------------------------------------------------- |
| **Счёт**            | **Позиции Счёта**, **Сумма**, **Статус**       | Сумма равна сумме позиций. Счёт нельзя оплатить дважды.           |
| **Платёж**          | **Способ Оплаты**, **Сумма**, **Статус**       | Платёж привязан к счёту. Сумма меньше или равна остатку по счёту. |
| **Банковский Счёт** | **Баланс**, **Валюта**, **Владелец**           | Баланс не уходит ниже допустимого лимита.                         |
| **Кредит**          | **График Платежей**, **Ставка**, **Статус**    | Одобрение только при пройденном скоринге.                         |
| **Транзакция**      | **Дебет/Кредит**, **Сумма**, **Метка Времени** | Двойная запись. Неизменяема после проведения.                     |

**События домена**:

| Событие                        | Данные                            | Потребители                      |
| ------------------------------ | --------------------------------- | -------------------------------- |
| **Счёт Выставлен**             | № счёта, № клиента, сумма         | Аналитика, Внутреннее управление |
| **Платёж Проведён**            | № платежа, № счёта, сумма, дата   | Аналитика, Внутреннее управление |
| **Кредит Одобрен**             | № кредита, сумма, ставка          | Аналитика                        |
| **Транзакция Зарегистрирована**| № транзакции, тип, сумма          | Аналитика                        |

### Внутреннее управление

**Назначение и границы**: Управление клиниками, персоналом больниц, инвентаризацией (ТМЦ), внутренними заявками и счетами. Обеспечивает операционную деятельность сети клиник.

**Источник данных**:
- "Медицинские данные";
- "Финтех";
- кадровые и складские системы.

**Домены-потребители данных**:
- **Финтех** - оплата заявок на ТМЦ, учёт списаний.
- **Аналитика и отчётность** - кадровая и операционная аналитика.

**Доменные агрегаты и сущности**:

| Агрегат              | Входящие сущности                          | Ключевые инварианты                              |
| -------------------- | ------------------------------------------ | ------------------------------------------------ |
| **Клиника**          | **Подразделения**, **Адрес**, **Профиль**  | Уникальный идентификатор клиники.                |
| **Сотрудник**        | **Должность**, **Квалификация**            | Один активный трудовой статус.                   |
| **Расписание/Смена** | **Слоты**, **Назначения Персонала**        | Сотрудник не назначается на пересекающиеся смены. |
| **Позиция ТМЦ**      | **Остаток**, **Единица Учёта**             | Остаток не отрицателен.                          |
| **Заявка На ТМЦ**    | **Перечень Позиций**, **Статус**           | Заявка проводится при наличии согласования.      |

**События домена**:

| Событие                | Данные                          | Потребители       |
| ---------------------- | ------------------------------- | ----------------- |
| **Заявка На ТМЦ Создана** | № заявки, позиции, № клиники | Финтех, Аналитика |
| **Персонал Назначен**  | № сотрудника, смена, клиника    | Аналитика         |
| **Инвентарь Списан**   | № позиции, количество, причина  | Финтех, Аналитика |

### Аналитика и отчётность

**Назначение и границы**: Портал самообслуживания и потоковые витрины: сотрудник получает отчёты по любым срезам в пределах своего уровня доступа и конструирует собственные отчёты. Не включает медицинские карты, истории болезней и результаты исследований — только обезличенные факты и финансово-управленческие данные. Преимущественно read-модель (CQRS-проекции над потоком событий). Уровень доступа применяется на уровне строк и столбцов (row-/column-level security) на основе оргструктуры и атрибутов пользователя.

**Источник данных**: "Медицинские данные", "Финтех", "Внутреннее управление".

**Домены-потребители данных**:
- **Портал самообслуживания** - отображение витрин и отчётов пользователям.

**Доменные агрегаты и сущности**:

| Агрегат                | Входящие сущности                              | Ключевые инварианты                                      |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------- |
| **Набор данных**       | **Срезы**, **Метрики**, **Временной Горизонт** | Строится только из разрешённых источников (без медкарт). |
| **Конструктор Отчёта** | **Измерения/Меры**, **Фильтры**                | Доступные поля ограничены уровнем доступа пользователя.  |
| **Подписка На Отчёт**  | **Расписание**, **Получатели**, **Формат**     | Рассылка только в пределах уровня доступа.               |

**События домена**:

| Событие              | Данные                              | Потребители                |
| -------------------- | ----------------------------------- | -------------------------- |
| **Витрина Обновлена**| № витрины, версия, отметка времени  | Портал, Управление данными |
| **Отчёт Сформирован**| № отчёта, № пользователя, статус    | Портал                     |

### Управление данными

**Назначение и границы**: Каталог схем и метаданных, контракты данных между контекстами, происхождение данных (lineage), поддержка единого языка. Обеспечивает совместимость и управляемость событийного обмена.

**Источник данных**:
- Схемы и метаданные, публикуемые всеми доменами в каталоге данных и их изменения.

**Домены-потребители данных**:
- **Все домены** - получают схемы, контракты и метаданные для совместимости событийного обмена.

**Доменные агрегаты и сущности**:

| Агрегат             | Входящие сущности                          | Ключевые инварианты                                            |
| ------------------- | ------------------------------------------ | -------------------------------------------------------------- |
| **Схема Данных**    | **Версия**, **Поля**, **Совместимость**    | Изменение схемы обратно совместимо (или новая мажорная версия). |
| **Контракт Данных** | **Издатель**, **Потребители**, **SLA**     | Контракт активен при согласовании сторон.                      |
| **Каталожная Запись** | **Источник**, **Приёмник**, **Преобразования** | Прослеживаемость происхождения данных.                    |

**События домена**:

| Событие                  | Данные                        | Потребители                      |
| ------------------------ | ----------------------------- | -------------------------------- |
| **Схема Зарегистрирована** | № схемы, версия, владелец   | Все домены                       |
| **Контракт Изменён**     | № контракта, версия, стороны  | Издатель и потребители контракта |
