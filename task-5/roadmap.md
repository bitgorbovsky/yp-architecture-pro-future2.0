# Стратегический план

Внедрение распределённого владения данными требует не только технологических
изменений, но и глубокого организационного преобразования. План синхронизирован
с этапами трансформации компании.

### Ключевые роли в распределённом владении данными:

- **Владелец продукта данных (ВПД)**: Отвечает за качество, актуальность и
  развитие данных как продукта (актива) внутри домена.
- **Инженер данных:** Технический специалист, отвечающий за конвейеры обработки
  данных внутри домена.
- **Аналитик данных**: Потребитель данных, создающий отчеты в системе
  самообслуживания.
- **Платформенная команда:** Централизованная команда, создающая инструменты
  самообслуживания для ВПД.

### Этап 1: Пилотный проект (0-6 месяцев)

- **Цель:** Проверка гипотез, отработка процессов в ограниченном масштабе.
- **Бизнес-цель:** Снижение нагрузки на DWH при построении отчетности по
  финансовым потокам нового банка.
- **Действия:**
    - Выбор пилотного домена: "Финтех-услуги".
    - Назначение первого ВПД.
    - Создание первой доменной витрины данных в облаке (Data Lakehouse).
    - Внедрение каталога схем событий в Kafka для обеспечения совместимости.
    - Настройка ремонтной очереди для обработки ошибок интеграции с Camel/DWH.
- **Результат:** Рабочий прототип витрины финансовых данных, доступный через
  Power BI.

### Этап 2: Масштабирование критических доменов (6-18 месяцев)

- **Цель:** Расширение доменной модели на основные бизнес-процессы клиники и
  ИИ-сервисов.
- **Бизнес-цель:** Ускорение вывода новых медицинских сервисов на рынок;
  обеспечение прозрачности управления клиниками.
- **Действия:**
    - Определение границ доменов: "Медицинские данные", "Внутреннее
      управление", "Аналитика и отчётность", "Управление данными".
    - Масштабирование платформы: внедрение семантического слоя и каталога
      данных для унификации метрик между доменами.
    - Внедрение антикоррупционных слоёв (Anti-corruption layers) при интеграции
      старых систем с новыми потоками событий Kafka.
    - Запуск потоковых витрин для аналитики в режиме "почти реальном времени"
      (финансовые отчёты, обслуживания пациентов, использование оборудования,
      работа с лабораториями).
    - Масштабирование команды: найм ВПД для каждого домена.
- **Результат:** Функционирующая экосистема из нескольких независимых доменов с
  единой точкой доступа к данным через портал самообслуживания.

### Этап 3: Полная трансформация и вывод старых систем из эксплуатации (18-36 месяцев)

- **Цель:** Переход к полностью децентрализованной архитектуре событийного
  типа.
- **Бизнес-цель:** Географическая экспансия; запуск новых продуктов; переход от
  пакетной отчетности к принятию решений в режиме, близком к реальному времени.
- **Действия:**
    - Отказ от точечных синхронных интеграций через шину Camel в пользу
      асинхронных событий Kafka во всех критических процессах.
    - Перевод доменной аналитики полностью на потоки данных (Stream
      Processing).
    - Интеграция новых направлений (фармацевтика, производство электроники) как
      новых доменов данных по готовым шаблонам самообслуживания от
      платформенной команды.
    - Полный вывод из эксплуатации старых систем или их перевод в режим "только
      чтение" для исторических справок.
- **Результат:** Целевая архитектура достигнута. Компания обладает гибкой
  ИТ-инфраструктурой, готовой к масштабированию по всем трем направлениям
  развития бизнеса.
